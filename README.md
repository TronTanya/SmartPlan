# SmartPlan

Компактный планировщик учебных задач для студентов: учёт заданий и сроков, автоматическое
распределение оставшейся работы по дням недели с учётом доступного времени.

Проект подготовлен для студенческой научной конференции. Приложение работает локально,
без платных API, облачных аккаунтов, авторизации и внешних моделей ИИ.

## Цель и гипотеза

**Цель:** помочь студентам учитывать сроки учебных заданий и распределять нагрузку с учётом доступного времени.

**Гипотеза исследования:** автоматическое распределение задач может упростить составление учебного
плана и помочь заранее обнаруживать нехватку времени.

Гипотеза пока **не проверена** на пользователях. Ниже описано, как проверять сам алгоритм и как
в будущем можно провести исследование с участием студентов.

## Возможности

- Создание, редактирование, отметка о выполнении и удаление задач.
- Поля задачи: название, предмет, срок, оставшаяся трудоёмкость (мин), приоритет, статус, заметки, дата создания.
- Проверка ввода: непустое название, положительная трудоёмкость для невыполненных задач, корректная дата, ограничения длины.
- Прошедшие сроки разрешены, но задача явно помечается как просроченная.
- Фильтры по предмету, статусу и приоритету; сортировка по сроку или приоритету.
- Сводка: активные задачи, просроченные, выполненные, оставшиеся часы — только по сохранённым данным.
- Недельный план: дата начала и доступные минуты на каждый из 7 дней (0 — день отдыха).
- Явный вывод нераспределённой работы: «не хватает времени до срока» или «остаток за пределами текущего плана».
- График Plotly «Учебная нагрузка на неделю»: запланированное и доступное время по дням.
- Экспорт задач и плана в CSV (UTF-8 с BOM, разделитель «;», десятичная запятая — для русской версии Excel).
- Демонстрационный набор из 6 вымышленных заданий (с префиксом «[Демо]»), без дублирования при повторной загрузке.
- Хранение задач и профиля доступного времени в SQLite (`data/smartplan.db`), создаётся автоматически.

## Установка и запуск

Нужен Python 3.11 или новее. Команды выполняются в папке `SmartPlan`.

```bash
python -m venv .venv
```

Активация виртуального окружения:

- **Windows (PowerShell):** `.venv\Scripts\Activate.ps1`
  (если запуск скриптов запрещён: `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`)
- **Windows (cmd):** `.venv\Scripts\activate.bat`
- **macOS / Linux:** `source .venv/bin/activate`

Затем:

```bash
pip install -r requirements.txt
streamlit run app.py
```

Приложение откроется в браузере по адресу http://localhost:8501.

Запуск тестов (из папки `SmartPlan`, с активированным окружением):

```bash
python -m pytest
```

## Алгоритм планирования

Используется прозрачный детерминированный алгоритм (эвристика), а не машинное обучение:

1. Отбираются невыполненные задачи.
2. Задачи со сроком раньше даты начала планирования считаются просроченными: они не планируются
   автоматически и выводятся отдельно с просьбой пересмотреть срок.
3. Остальные задачи сортируются: ближайший срок → более высокий приоритет → ID задачи (стабильный порядок).
4. Оставшаяся трудоёмкость каждой задачи распределяется по дням, начиная с самого раннего дня со свободным временем.
5. Работа никогда не назначается после срока (день срока включается).
6. Доступное время дня никогда не превышается.
7. Задача может быть разделена между несколькими днями.
8. Нераспределённые минуты сохраняются и показываются явно:
   - если срок внутри 7-дневного горизонта — «Не хватает времени до срока»;
   - если срок позже горизонта — «Остаток за пределами текущего плана» (это не считается срывом срока).

Все расчёты ведутся в целых минутах; часы используются только для отображения.
Результат — выполнимый эвристический план; математическая оптимальность не утверждается.

Любое изменение задач, даты начала или доступного времени помечает ранее составленный план как устаревший.

## Тесты

`tests/test_planner.py` проверяет: приоритет ближайшего срока, разрешение равных сроков по приоритету,
стабильный порядок, разделение задач по дням, соблюдение дневного лимита, отсутствие работы после срока,
включительность дня срока, исключение выполненных задач, дни с нулевым временем, отдельный учёт
просроченных задач, сохранение нераспределённой работы, метку «за пределами плана», пустой список,
реальное предупреждение в демонстрационном наборе. Для каждой задачи проверяется, что
запланированные + нераспределённые минуты равны исходной оставшейся трудоёмкости.

`tests/test_database.py` проверяет создание, чтение, изменение, удаление, отметку о выполнении,
сохранение данных между переинициализациями, настройки времени, защиту от дублирования демо-данных
и корректное хранение строк со спецсимволами.

Во всех тестах используется явная дата начала планирования, поэтому результат не зависит от текущей даты.

## Демонстрация

1. Нажмите «Загрузить демонстрационные задачи». Будут добавлены 6 вымышленных заданий со сроками
   относительно выбранной даты начала планирования (одно уже выполнено).
2. На вкладке «План на неделю» оставьте профиль времени по умолчанию (120, 120, 90, 0, 120, 60, 90 минут)
   и нажмите «Составить план».
3. Планировщик покажет реальную нехватку времени: лабораторной работе по физике не хватит 2 ч до срока,
   а эссе по истории получит «остаток за пределами текущего плана».
4. Увеличьте время в первые дни (например, до 180 минут) и составьте план заново — предупреждение исчезнет.

Повторное нажатие кнопки загрузки не создаёт дубликатов. Если демо-задачи нужно убрать, удалите их
в списке или удалите файл `data/smartplan.db` при остановленном приложении.

## Воспроизводимый эксперимент (проверка алгоритма)

Цель — проверить, что алгоритм соблюдает ограничения и корректно сообщает о нехватке времени.
Это проверка алгоритма, а **не** доказательство пользы для студентов.

1. **Подготовка данных.** Составьте несколько наборов задач (например, 5, 10 и 20 задач) с разными
   сроками, приоритетами и трудоёмкостью, и несколько профилей времени (равномерный, с днями отдыха,
   с явной нехваткой времени). Зафиксируйте дату начала и сохраните наборы, чтобы опыт можно было повторить.
2. **Генерация планов.** Для каждой пары «набор × профиль» вызовите `planner.build_plan(tasks, start, capacities)`.
   Алгоритм детерминирован: одинаковые входные данные дают одинаковый результат.
3. **Измерения** для каждого плана:
   - число нарушений дневного лимита (дни, где запланировано больше доступного);
   - число назначений после срока задачи;
   - суммарное запланированное время;
   - суммарное нераспределённое время, отдельно «до срока» и «за пределами плана»;
   - проверка баланса: запланировано + не распределено = исходная трудоёмкость для каждой задачи.
4. **Результаты.** Сведите измерения в таблицу. Ожидаемый результат для первых двух показателей — ноль;
   в материалы конференции включайте только фактически полученные значения.

### Возможное будущее исследование с пользователями

Отдельно от проверки алгоритма можно провести исследование со студентами: например, сравнить время
составления недельного плана вручную и в SmartPlan, а также долю случаев, когда нехватка времени была
обнаружена заранее. Такое исследование пока **не проводилось**; любые выводы о пользе для студентов
возможны только после него.

## Ограничения

- Оценки трудоёмкости вводит пользователь; качество плана зависит от их точности.
- Алгоритм не учитывает усталость, сложность переключения между задачами и зависимости между задачами.
- Система не гарантирует выполнение задач и не гарантирует улучшение успеваемости.
- Планировщик использует правила распределения, а не обученную модель ИИ.
- План строится на 7 дней; составленный план не сохраняется между запусками и пересчитывается кнопкой.
- Приложение рассчитано на одного пользователя и локальный запуск.
